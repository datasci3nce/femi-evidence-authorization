**Created:** 2026-11-08. **State:** offline-tested *execution packet*, not an executed study, public preregistration, or validated model-result bundle. **API calls performed by packet author: zero.** The package contains no downloaded benchmark data, proprietary raw contracts, API keys, or model weights.

## Quick index

| Component | Distinct sources | Arms | Planned executions | Research question |
|---|---:|---|---:|---|
| CNLI-TRANSFER-1 | 48 different contracts, one hypothesis per contract | 3 evidence regimes × 2 availability wordings | 288 anchor-model calls | Does the FEMI missing-authority effect carry into full-document legal NLI? |
| FEVEROUS-TRANSFER-1 | 48 different claim IDs, at least 12 with table evidence | 3 regimes × 2 wordings | 288 anchor-model calls | Does the effect survive evidence packets combining text and structured cells? |

## 2. FEVEROUS — freeze and run as a distinct domain

```bash
python src/build_transfer.py feverous \
  --input /path/to/feverous_dev_challenges.jsonl \
  --wiki-jsonl /path/to/feverous_wiki_pages.jsonl \
  --n 48 --min-table 12 --out runs/feverous
python src/run_and_score.py preflight --dir runs/feverous
python src/run_and_score.py run --dir runs/feverous --models models.anchor.json
```

After audit, use the same explicit `--execute` / `analyze` process from Stage 1. The adapter resolves annotated `sentence`, `cell`, `header_cell`, `table_caption`, `item`, `section`, `title` elements and appends available contextual headings. It fails instead of silently fabricating missing evidence. It selects the **first gold evidence set** and requires a minimum of 12 table-containing cases; the `FREEZE.json` records actual modality counts.

**Critical caveat:** this is *oracle-selected evidence*, not realistic Wikipedia retrieval. For `NOT ENOUGH INFO`, an evidence packet may exist while being insufficient: the model should DEFER. This differs from the trusted-absent condition, where no designated source record is provided. Run a human packet audit on several text, table and mixed records before using paid inference.

## 4. d1-3B — source-faithfulness, unsteered vs steered

```bash
python src/prepare_d1.py \
  --response-file /path/to/RAGTruth/dataset/response.jsonl \
  --source-file /path/to/RAGTruth/dataset/source_info.jsonl \
  --train-pairs 24 --dev 40 --test 100 --out runs/d1
```

This makes 24 *paired training sources* (one supported and one annotated unsupported response for each source), 40 **source-disjoint** dev examples, and 100 **source-disjoint** labeled test examples (balanced 50/50). Gold is `supported=1` if RAGTruth has zero annotated unsupported spans; this is a coarse approximation of semantic evidence attribution, and a human audit of uncertain categories (`implicit_true`, null etc.) is needed. RAGTruth's publisher train/test split is preserved.

Run on Colab GPU / local CUDA. Use `pip install -r requirements-gpu.txt`, then:

```bash
python src/d1_local.py list-hooks --dir runs/d1
# Inspect which hook path is appropriate; copied path must actually fire ONCE per system_one call.
python src/d1_local.py fit --dir runs/d1 --hook-name FULL_EXACT_MODULE_PATH
python src/d1_local.py test --dir runs/d1 --hook-name FULL_EXACT_MODULE_PATH
```

Arms: (1) same question unsteered, (2) explicit evidence-boundary question wording, (3) **nonzero** activation steering direction learned from the source-matched TRAIN pairs with dose picked on DEV, (4) same-norm random-direction sham. Holdout TEST is not used for direction/dose selection. The code halts if the hook is missing, multi-fired, or returns the wrong tensor shape. The model's public `system_one` interface is documented, but the internal module hook is **not guaranteed stable across model revisions**, so successful local GPU operation is not claimed here. If hook discovery fails, run/report the two behavioral arms separately rather than pretending the activation study succeeded.

The study is *not* a test of the deterministic authorization gate: source presence is decidable in code. It is specifically a test of natural-language *support* checking. Primary metric: heldout false acceptance of unsupported answers, with paired change against baseline and sham. Secondary: Brier, overall accuracy, supported-answer acceptance, task-family breakdown. The fixed holdout must never be used to tune hook, dose, prompt, or threshold.

## Safeguards against invalid conclusions

1. No benchmark gold label, evidence-set label, hypothesis annotation, or metadata identifying `clean`, `selection` or `population` is put into an input prompt. Gold fields live only in local private scoring files.
2. Complete response inventory, SHA256 matching, unique trial IDs, valid JSON scoring, source-disjoint group IDs and correct evidence regimes are tested before publication.
3. **All model requests are new transfer interfaces.** Failure to transfer does not invalidate the original FEMI-2/2R/4 result, and success does not identify the linguistic mechanism.
4. `cited_evidence` names alone do **not** prove false positive attribution. Manual rationale audit is mandatory, including distinguishing mention of missing support from a claim that evidence certified something.
5. Written protocol is *locally frozen when the data manifest is created*; it is **not externally preregistered**. Preserve all intended and observed deviations.
6. No manufactured positive result is required. The experiment succeeds when its validity gates pass and all results, positive and negative, are accurately reported.
